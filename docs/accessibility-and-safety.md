# Accessibility, privacy, and quality checklist

Use this checklist for every custom visual you add. A visual that looks compelling can still be unsuitable for a production report.

## Accessibility and usability

- [ ] The visual has a descriptive title and alternative text.
- [ ] Important information is not conveyed by color alone.
- [ ] Text and marks have sufficient contrast and readable sizes.
- [ ] Keyboard focus and navigation are usable.
- [ ] Screen-reader behavior has been checked where supported.
- [ ] Tooltips and labels explain units, date ranges, and aggregation.
- [ ] A native or tabular alternative is available for essential information.
- [ ] The visual remains understandable at smaller sizes and in high-contrast settings.

## Privacy and security

- [ ] Publisher identity and official source have been verified.
- [ ] Data access, network calls, storage, and external services are understood from publisher documentation.
- [ ] No sensitive or personal data is used in this learning project.
- [ ] The organization's Power BI administrator has approved the visual for organizational use.
- [ ] HTML, SVG, or other user-supplied content is treated as untrusted; no unreviewed scripts or markup are embedded.
- [ ] The visual's terms and any data-processing disclosures have been reviewed.

## Reliability and performance

- [ ] The visual has been tested with expected data volume and filter combinations.
- [ ] Totals match a native Power BI table or independently checked result.
- [ ] Cross-filtering, tooltips, drill-through, and export behavior have been tested.
- [ ] Desktop and target Service/mobile behavior have been checked.
- [ ] The exact visual version and test date are recorded.
- [ ] A native alternative is documented in case the visual is unavailable or blocked.
